# Quarantine and Manual Retry

## 保存方針

- 隔離先を `lazyweb/quarantine/<入力フォルダ名>/` に固定する。
- 元の一時ファイル名を変更せずに保存する。
- 隔離時刻から最低90日間保持する。90日経過は削除許可ではなく、手動レビュー可能になる時点とする。
- 自動削除、ローテーション、上書きを行わない。
- 削除は、対応する正式出力と成功manifestと`PROCESSED`の整合を確認し、ユーザーが対象パスを明示して承認した場合だけ行う。
- 未解決の失敗、監査・調査中、または対応manifestが特定できないファイルは期限を設けず保持する。
- 隔離ファイルをGit管理対象にしない。

## 手動隔離

1. 対象を同じslugの一時ファイル1件に限定する。内容を表示しない。
2. 移動元と移動先をプロジェクト相対パスで明示する。
3. 移動先ディレクトリを作り、移動先が未使用であることを確認する。
4. 移動前のSHA-256を計算する。
5. 同一ファイルシステム上でハードリンクを移動先へno-overwriteで作成する。
6. 移動先のSHA-256が一致した場合だけ移動元名を`unlink`する。不一致またはリンク失敗時は移動元を残す。
7. 次の値だけを `<一時ファイル名>.quarantine.json` に記録する。本文、URL、認証情報は記録しない。
   - `schema_version`
   - `quarantined_at`
   - `retain_until`
   - `source`
   - `destination`
   - `sha256`
   - `reason`

隔離ファイルとreceiptの既存物は変更・削除しない。異なるファイルシステムでハードリンクできない場合は停止し、コピーや削除へ自動フォールバックしない。

## 失敗後の手動再実行

1. 過去の実行ログ、対応する`.manifest.json`、隔離receiptだけを確認し、本文や隔離ファイルを不要に表示しない。
2. `status`と`missing_or_stop_reason`から停止原因を特定する。
3. 入力不足はユーザーが修正したことを確認する。skillが`article.md`、`lazyweb-research.md`、`READY`を生成・補完しない。
4. 同じslugの正式出力が存在する場合は再実行しない。既存成果物の扱いについてユーザーの明示指示を待つ。
5. 同じslugの一時ファイルが残る場合は再実行しない。上記手順で1件ずつ隔離する。
6. `READY`あり、`PROCESSED`なし、必須入力あり、正式出力なし、同slug一時ファイルなしを再確認する。
7. validatorの`prepare`を明示入力1件に対して実行する。
8. `status: ready`の場合だけ、返された一時出力パスへLLMがdraftを作成する。
9. validatorの`finalize`を実行する。LLMが正式出力、ログ、manifest、`PROCESSED`を直接作らない。
10. 過去ログ、過去manifest、隔離ファイル、隔離receiptを残したまま、今回の結果を確認する。

手動再実行でもWeb検索、外部URL取得、画像生成、Git操作、記事公開を行わない。
